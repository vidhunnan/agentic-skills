The directions

A · type contrast
Marked Output
Believes: the page is machine output, and the only human thing on it is the mark.

One face, three sizes. Hierarchy from case, weight and colour — never from scale.
B · layout structure
Running Log
Believes: a record is a sequence of dated entries, not a set of titled sections.

Numbered gutter, append-only made visible — superseded things struck, not removed.
C · density
Accession
Believes: every claim should carry where it came from, at the point you read it.

A provenance rail on every object. "Provenance unknown" is a first-class label.

Merging

B's gutter with A's type. The dated, numbered sequence is the strongest structural idea here, and it does not depend on B's serif. A's single-face discipline would make it far less blog-like.

C's provenance rail, applied only to specimens. The rail is convincing on a record and heavy everywhere else. Scoped to the artifacts, it defends the "records read as a gimmick" failure better than any of the three do whole.

A's matrix in any of them. The three-column table reads well in all three and is nearly identical across them — which suggests it is settled, not that it is undifferentiated.

Constraints honoured

Records verbatimYes — ##, ** and *(…)* render as literal source in all three. No badge, pill or icon stands in for a mark.
Path carriedYes — the specimen names its file in all three.
Nothing types itselfYes — zero JS, zero animation, zero transitions in all three.
Redline's meaningYes — --red appears only on unrecorded reasons, unanswered questions and superseded entries. Never for emphasis.
PaletteYes — all 11 tokens copied verbatim from globals.css, both modes. Nothing re-derived.
Reads with JS offYes — no scripts at all.
No unsourceable claimYes — counts and paths are real. One caveat: local system fonts only, because the constraint forbids CDN dependencies. Type here indicates register, not the final faces.
