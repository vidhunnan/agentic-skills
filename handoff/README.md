# Handoffs — Where did we leave off?

**Question:** Where did we leave off?
**Tense:** point-in-time
**Status:** snapshot
**Written by:** either (usually `/handoff-generator`)
**Lifecycle:** Stale by design. The latest one wins; an old handoff is **not** current state.

"Morning — what'd I miss?" A brief that carries work across a boundary: chat → code, code → chat, session → session, you → a teammate. The file is the only thing that survives the hop.

> **Path note.** The canonical location for this tier is `docs/handoffs/`, but this repo's `handoff-generator` skill writes to `handoff/` and had files here first — so `repo-setup` **adopted** the existing name rather than creating a duplicate. Existing paths beat canon.

## What goes here

- `handoff-{from}-to-{to}-{date}-{slug}.md`, generated by `/handoff-generator`.
- A comprehensive project handoff: what this is, snapshot/current state, progress & timeline, features/components, decisions made, what this session changed, open questions, files referenced, next actions, and notes for the receiver.

## What does NOT go here

- Anything that should outlive the hop. If a decision was made, it belongs in `../docs/decisions/` too — a handoff is a snapshot, and snapshots go stale.
- Verbatim minutes. A handoff carries enough state — progress, what changed, decisions — for the receiver to continue, but it's **a briefing aimed at what's next**, not a transcript of every exchange.

## Reading these

**Read the most recent one first, and check its date.** An old handoff describes a project that no longer exists. If it contradicts the code or the changelog, the code and the changelog win.

## Template

Copy `_TEMPLATE.md`, or just run `/handoff-generator` — it interviews you and fills this in.
