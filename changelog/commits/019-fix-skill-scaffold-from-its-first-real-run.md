  inside, with the rule stated.

- when_to_use was absent from the generated skeleton, so every generated
  skill crammed triggers into description. Now in the skeleton and Step 3,
  with the ~1536-char combined cap noted.
- Step 1 cited branch-naming as a skill that registers no protocol block.
  It does, in its Step 5. Corrected to design-brief.
- Step 6.2 let README and skills.ts disagree on a group note. SkillGroup.note
  is a required field of the type, so the note is now mandatory in both and
  must match.
