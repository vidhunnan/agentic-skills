## Commit message

Opens the design territory. The premise: code has git log, and design has
nothing. A Figma file is a snapshot of the winner -- it never holds the
problem, the directions that were killed, why the survivor won, or what was
traded away.

- design-setup scaffolds the design context stack (briefs, research,
  explorations, decisions, specs, system) with repo-setup's rules:
  detect-map-confirm, additive-only, one confirmation gate, check mode, and
  a minimal preset. No design changelog tier -- changelog/ is generated
  from git and is the only tier entitled to say what shipped.
- design-brief interviews into the stated intent every later skill cites,
  and marks unanswered sections (not stated) rather than inventing success
  criteria.
- design-decisions logs a fork as an append-only ADR carrying two fields
  architectural ADRs usually omit: what we gave up, and what would make us
  revisit.

All three are restricted to interview, record, structure, check. None makes
a design decision or generates a visual. Inventing a rationale is worse here
than in code because there is no diff to catch it.

## Changes in detail

### `skills/design-setup/SKILL.md` (new)

- Ten steps mirroring `repo-setup`: read-only survey in descending authority (CLAUDE.md declared paths → directory census → root files → repo-shape flags), a name lexicon, content sniffing, a HIGH/MEDIUM/LOW confidence ladder that keeps the interview to at most four questions, a single write gate, additive-only writes, CLAUDE.md registration, a gated sibling offer, reconcile-on-re-run, and a `check` mode with zero writes.
- Canon table defines six tiers under `design/` and explicitly refuses a seventh: no design changelog, because `changelog/` is generated from git and a hand-written parallel would be hypothesis presented as truth.
- Names the collisions with the code stack (`docs/design/`, `concepts/`, `explorations/`, `research/`, `handoff/`) and requires reading `skill:repo-setup`'s routing table first so the two stacks never claim one path.
- Tier templates carry the two load-bearing fields: the observation/interpretation split in research, and *kept or killed — and why* in explorations.

### `skills/design-brief/SKILL.md` (new)

- Eight steps. Step 2 reads the current conversation before asking anything, so an interview that has effectively already happened isn't repeated.
- Step 3's two rounds each carry an explicit "I don't know yet" option; Step 4 classifies every section stated or not stated and rules out two things that don't count as stated — inference from the product category, and wholesale-drafted sections the user merely agreed to.
- Step 7 makes revision append a dated note quoting the prior text verbatim, rather than silently replacing it.

### `skills/design-decisions/SKILL.md` (new)

- Twelve steps. Inherits `decisions-logger`'s machinery — normalized claims, the dedup/supersession comparison, the source firewall, the reject ledger, the frozen-body byte check, the four follow-up triggers — and inverts its emphasis: with almost nothing to mine, the fast path is the common path and evidence is captured in the moment.
- Adds two required ADR sections architectural ADRs usually omit: `## What we gave up` and `## What would make us revisit`.
- Uses a distinct `design-decisions-index` marker so the two decision tiers never clobber each other's index region.

### `docs/prds/design-setup.md`, `docs/prds/design-brief.md`, `docs/prds/design-decisions.md` (new)

- One PRD per skill with numbered requirements, non-goals, risks and open questions. Each records the risk that dominated its design: ceremony for `design-setup`, fluent fabrication for `design-brief`, and undetectable fabrication for `design-decisions`.
