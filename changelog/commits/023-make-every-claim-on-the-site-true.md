## Commit message

Three things the page stated were false.

1. The explorations tier contradicted itself in three places. CLAUDE.md's
   skill:design-setup block declares docs/concepts/website/ (adopted, because
   the design stack is additive-only and never moved the drafts).
   skills.ts said design/explorations/. Nothing was on disk at either path
   under that name -- so the site rendered a folder that does not exist, and
   page.tsx built the design section's closing argument on it.

   This is exactly the declared-vs-disk contradiction repo-setup Step 2e
   exists to detect, shipped by the repo that sells the check. Worth saying
   plainly rather than quietly correcting. Verification now asserts every
   folder in CONTEXT_STACK and DESIGN_STACK resolves on disk AND appears in
   a CLAUDE.md routing table -- a standing check, not a one-off.

2. Six hardcoded "six"s while rendering eleven skills, including the meta
   description served to every search engine and link preview.

   Fixed as a class, not as instances: TOTAL_SKILLS and TOTAL_SKILLS_WORD
   are derived from SKILL_GROUPS. ADR 0016 made the skill *data*
   single-source and left the copy *about* it as string literals, which is
   precisely why it went stale. It can't now.

3. "Every fact each one writes is pulled from your repo" is true of the code
   skills and false for design-brief, design-decisions and exploration-log,
   which are interview-driven and cannot read a repo. Rewritten to the
   guarantee both halves actually share: nothing is invented -- the code
   skills read it, the design skills ask, and mark what you couldn't answer.

Also: skill-scaffold's site description picked up the skill-creator
disambiguation it was missing, and the keyword set -- which predated the
design skills entirely -- gained the design terms.
